**作者**: 系统架构组

## 1. 引言

本文档描述了一个高度模块化的粒子系统架构，旨在提供灵活、可扩展的粒子效果生成能力。系统核心由 `ParticleSystem`、`ParticleEmitter`、`Particle` 以及多个可插拔的 `Module` 组成，通过 `ModuleStack` 在不同阶段组织模块的执行顺序。该设计借鉴了现代游戏引擎（如Unity、Unreal）的粒子系统思想，强调解耦、复用与性能。

## 2. 核心概念

- **ParticleSystem**: 顶级容器，管理多个发射器，拥有系统级的生成和更新模块堆栈。
- **ParticleEmitter**: 粒子发射器，负责产生和管理粒子，拥有独立的发射器级和粒子级模块堆栈。
- **Particle**: 单个粒子实例，包含位置、速度、颜色、大小、生命周期等基本属性，可通过模块扩展自定义属性。
- **Module**: 最小的功能单元，实现具体的粒子行为（如重力、颜色渐变、旋转等）。每个模块仅关注单一职责。
- **ModuleStack**: 模块的有序列表，在特定阶段按顺序执行所有模块。堆栈支持动态添加、移除、启用/禁用模块。

模块堆栈 (ModuleStack) 是模块的容器，每个堆栈中可以按顺序放入多个具体功能模块（如“恒定加速度模块”、“颜色渐变模块”），执行时会依次调用。

### 3.2 模块堆栈划分

每个堆栈对应粒子系统生命周期中的一个特定阶段：

| 堆栈名称                      | 所属组件            | 执行时机                            |
| ------------------------- | --------------- | ------------------------------- |
| SystemSpawnModuleStack    | ParticleSystem  | 系统每帧生成新发射器或控制全局生成参数时执行          |
| SystemUpdateModuleStack   | ParticleSystem  | 系统每帧更新时执行，处理全局环境（如风力、重力场）       |
| EmitterSpawnModuleStack   | ParticleEmitter | 发射器每帧决定是否生成新粒子时执行，可修改生成速率、生成形状等 |
| EmitterUpdateModuleStack  | ParticleEmitter | 发射器每帧更新时执行，处理发射器自身的运动、旋转等       |
| ParticleSpawnModuleStack  | ParticleEmitter | 每个新粒子生成时执行，用于初始化粒子的属性           |
| ParticleUpdateModuleStack | ParticleEmitter | 每帧更新所有活跃粒子时执行，处理粒子运动、颜色变化等      |
| ParticleRenderModuleStack | ParticleEmitter | 每帧渲染粒子前执行，准备渲染数据（如材质、排序、合批）     |

### 3.3 模块接口定义（todo）

所有模块实现统一的接口 `IModule`，以便堆栈能够统一调用：

```csharp
interface IModule {
    // 模块名称（用于调试和编辑）
    string Name { get; }
    
    // 执行模块逻辑，context 提供当前阶段所需的数据和环境
    void Execute(ModuleContext context);
    
    // 克隆模块（用于复制预设）
    IModule Clone();
}
```

根据执行阶段不同，`ModuleContext` 会提供特定的访问接口，例如：
- `SpawnContext`: 可访问系统/发射器的生成参数，并提供生成粒子的方法。
- `UpdateContext`: 包含当前时间步长、全局属性，并提供粒子列表的访问。
- `RenderContext`: 提供渲染队列、材质设置等。

### 3.4 粒子数据设计（todo）

粒子数据通常需要高性能访问，建议采用结构体数组（SoA）或紧凑的结构存储：

```csharp
struct Particle {
    float3 position;
    float3 velocity;
    float4 color;
    float size;
    float life;        // 当前生命值（0~1 或剩余时间）
    float startLife;    // 初始生命周期
    // 可扩展的自定义数据（通过额外数组或动态分配）
}
```

对于自定义属性，可以通过模块动态添加，并在粒子内存池中预留空间（如使用 `byte[]` 或额外数组）。

## 4. 模块生命周期与执行流程

### 4.1 系统更新循环

每帧（或每 tick）执行以下步骤：

1. **系统更新阶段**：
   - 执行 `SystemUpdateModuleStack`，更新全局环境。
   - 对于每个发射器，执行其 `EmitterUpdateModuleStack`。
2. **发射器生成阶段**：
   - 对每个发射器，执行 `EmitterSpawnModuleStack` 决定本次生成粒子的数量。
   - 对于每个要生成的新粒子，执行 `ParticleSpawnModuleStack` 初始化属性。
3. **粒子更新阶段**：
   - 对每个发射器，遍历其活跃粒子，执行 `ParticleUpdateModuleStack` 更新粒子状态。
4. **粒子渲染阶段**：
   - 对每个发射器，执行 `ParticleRenderModuleStack` 准备渲染数据，提交渲染指令。

### 4.2 模块间数据传递（重要）

模块之间可能需要共享临时数据（例如，一个模块计算出的力供后续模块使用）。可以在 `ModuleContext` 中提供“黑板”（Blackboard）机制，允许模块读写任意键值对，但需注意线程安全（通常粒子系统单线程更新）。

## 5. 模块类型示例

以下是一些典型模块及其所属堆栈：

| 模块名称      | 所属堆栈                      | 功能描述                   |
| --------- | ------------------------- | ---------------------- |
| 恒定重力      | ParticleUpdateModuleStack | 每帧给粒子施加恒定向下的加速度        |
| 初始速度（形状）  | ParticleSpawnModuleStack  | 根据发射器形状（锥、球）计算初始速度     |
| 颜色随生命周期变化 | ParticleUpdateModuleStack | 根据粒子寿命渐变颜色             |
| 大小随机范围    | ParticleSpawnModuleStack  | 在指定范围内随机初始化粒子大小        |
| 发射器旋转     | EmitterUpdateModuleStack  | 让发射器围绕某点旋转，影响生成位置      |
| 风力场       | SystemUpdateModuleStack   | 在全局空间中添加风场，影响所有粒子      |
| 粒子排序（深度）  | ParticleRenderModuleStack | 根据相机距离对粒子进行排序（实现半透明正确） |

## 6. 数据流与依赖

- 模块不应直接引用其他模块，仅通过上下文访问系统/发射器/粒子的公共状态。
- 粒子系统采用自顶向下的数据流：系统持有发射器列表，发射器持有粒子列表和模块堆栈。
- 为了避免每帧遍历所有粒子时的虚函数开销，可以考虑将模块对粒子的操作批量化，例如每个模块提供一个 `ProcessParticles(Span<Particle> particles)` 方法，由堆栈统一调用。

## 7. 性能考虑

- **内存布局**：粒子数据应尽可能紧凑，使用结构体数组（AoS）或数组结构体（SoA）以利用CPU缓存。
- **模块执行优化**：对于没有每帧逻辑的模块，可以跳过执行。允许模块标记是否需要每帧更新。
- **并行处理**：在多核系统上，可以将不同发射器或不同区域的粒子更新任务并行化，但需注意模块对共享数据的访问。
- **粒子池**：使用对象池管理粒子，避免频繁分配/释放内存。

## 8. 序列化与编辑器支持

- 每个模块应可序列化为某种数据格式（JSON、XML或二进制），以便保存为预设。
- 编辑器应允许用户通过拖拽方式向堆栈添加模块，并配置模块参数。
- 模块参数应支持基本类型（float, int, bool, Vector3, Color）以及曲线（AnimationCurve）等复杂类型。

## 9. 扩展性设计

- 用户可以自定义实现 `IModule` 接口，注册到系统中。
- 系统应提供模块工厂，根据类型名称创建模块实例。
- 允许第三方开发者创建模块插件，动态加载。

## 10. 结论

本文档提出的模块化粒子系统架构通过明确的职责划分和灵活的模块堆栈，能够满足从简单到复杂的粒子效果需求。后续实现时需重点关注模块执行效率、数据布局以及编辑器集成，以确保系统的实用性和高性能。
